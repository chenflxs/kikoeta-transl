# Kikoeta Transl（kt）架构方案

> 先方案、后代码。本文约定：GalTransl = **gt**，VoiceTransl = **vt**，本项目 = **kt**。
> kikoeta 现有翻译只处理标题 / 文件名，不覆盖媒体听写与字幕翻译。

## 1. 定位

kt 是面向 kikoeta 的 **Windows 桌面翻译伴侣**（Mac / Linux 计划中，不做移动端）。

- 输入任意音视频，或未翻译的字幕 / 歌词。
- 输出 kikoeta 可直接使用的字幕 / 歌词（优先 `.lrc`，兼 `.srt` / `.vtt`）。
- 内置完整 gt；大模型翻译 **进程内调用 gt 模块**，不走 vt 的 `translate.py` 子进程。
- 转码、人声分离、听写参考 vt。
- UI 与 kikoeta 保持同一套视觉语言，但不嵌入 kikoeta 客户端（避免把 Python / 模型栈塞进 Flutter+Rust 播放器，也避免污染移动端）。

许可：gt 为 GPLv3。内置完整 gt 后，kt 也应按 GPLv3 发布。kikoeta 本体可继续 MIT。

## 2. 工作流

```text
输入
 ├─ 媒体（音频 / 视频）
 │    └─ [必做] ffmpeg 转码为 16k/mono/pcm
 │         └─ [可选] UVR 人声分离
 │              └─ [必做] ASR 听写
 │                   └─ [可选] 小参数模型矫正听写
 │                        └─ [可选] gt 大参数模型翻译
 │                             └─ 导出字幕 / 歌词
 └─ 字幕 / 歌词（.srt / .lrc / .vtt / .ass）
      └─ 解析为中间 JSON（跳过转码 / UVR / ASR）
           └─ [可选] 小参数模型矫正
                └─ [可选] gt 大参数模型翻译
                     └─ 导出字幕 / 歌词

工作流结束后删除转码与人声分离等中转文件。
```

除媒体路径的转码与 ASR 外，UVR / 矫正 / 翻译均可独立开关。音频 / 视频必须走 ASR，不能关闭；直接输入字幕 / 歌词时自动跳过听写。

### 2.1 跳过规则

| 输入 | 转码 | UVR | ASR | 矫正 | 翻译 |
| --- | --- | --- | --- | --- | --- |
| 音视频 | 必做 | 可选 | 必做 | 可选 | 可选 |
| 未翻译字幕 / 歌词 | 跳过 | 跳过 | 跳过 | 可选 | 可选 |

补充：

- 音频 / 视频必须 ASR，UI 不提供关闭开关。已有字幕时应直接投入字幕 / 歌词文件，而不是投媒体并跳过听写。
- 关闭翻译：只输出原文时间轴（媒体来自 ASR，字幕来自原文件）。
- 关闭矫正：ASR 或字幕原文直接进入下一阶段。
- 媒体任务至少包含转码 + ASR + 导出；字幕任务至少包含解析 + 导出。

### 2.2 中间格式

全管线统一为带时间轴的 JSON，对齐 vt 的 `srt2prompt`：

```json
[
  { "start": 1.23, "end": 4.56, "message": "原文或矫正后文本" }
]
```

- 时间轴只在导出时写回 SRT / LRC / VTT。
- 矫正与翻译只改 `message`，不改 `start` / `end`。
- 需要保留原文时另存 `src_message`，供双语导出与 gt 的 `org_message` 使用。

## 3. 总体架构

Flutter 桌面 UI + Python engine。UI 不直接调用 Python 模块；engine 内嵌完整 gt。

```text
┌──────────────────────────────────────────┐
│  kt Flutter UI（kikoeta 视觉语言）        │
│  任务 / 模型 / 听写参数 / 模型参数 / 字典 │
│  输出 / 设置                             │
└──────────────────┬───────────────────────┘
                   │ 本地 HTTP JSON
                   │ 127.0.0.1 + SSE/轮询进度
┌──────────────────▼───────────────────────┐
│  kt Python engine                        │
│  管线编排 · 阶段开关 · 任务队列 · 清理    │
│    ├─ transcode   ffmpeg（参考 vt）       │
│    ├─ separate    UVR ONNX（参考 vt）     │
│    ├─ asr         CrispASR + aligner      │
│    ├─ correct     小参数模型矫正（新建）   │
│    ├─ translate   进程内调用 gt 模块      │
│    └─ export      LRC / SRT / VTT         │
│  vendor: GalTransl / ffmpeg / crispasr    │
└──────────────────────────────────────────┘
                         │
                         ▼
              kikoeta 歌词库（可选写出）
              lyrics/RJ######/*.lrc
```

选择本地 HTTP 而不是 stdio：engine 内部使用 `127.0.0.1:18765` 供桌面 UI 调用，同时提供 `127.0.0.1:2370` 服务端口供 kikoeta 通过 HTTP 上传输入文件、查询进度并下载输出；设置开启远程访问后服务监听 `0.0.0.0:2370`，便于安卓设备通过局域网或 DDNS 访问。

不采用的方案：

- 把管线嵌进 kikoeta：模型、ffmpeg、ONNX、Python 体积与生命周期都不适合播放器。
- 复刻 vt 的 PyQt UI：无法与 kikoeta 视觉对齐，后续也难互相跳转。
- 像 vt 一样 `subprocess` 调 `translate.py`：用户要求直接调用 gt 模块，且可避免 Windows 管道编码问题。

## 4. 各阶段设计

### 4.1 转码（必做，仅媒体）

参考 vt：

```text
ffmpeg -y -i <input> -acodec pcm_s16le -ac 1 -ar 16000 <stem>.16k.wav
```

- 视频只抽音轨，不做画面处理。
- ffmpeg / ffprobe 优先使用随包 `bin/ffmpeg`，否则回退系统 PATH。
- 输出写到任务工作区，不覆盖用户原文件。
- 任务成功、失败或取消后都删除 `.16k.wav` 及 UVR 中间件。

### 4.2 人声分离（可选）

参考 vt 的 `separate.py`：

- ONNX MDX / ConvTDF，目标 `vocals`。
- Windows 使用 `DmlExecutionProvider`。
- ASMR 干声场景默认关闭。
- 模型文件放 `bin/separate/*.onnx`，UI 扫描列表。

### 4.3 听写（必做，仅媒体）

参考 vt 的 CrispASR 工作流：

1. 将 wav 拷入临时 job 目录。
2. 调用 `crispasr` + 主模型 + aligner，产出 SRT。
3. SRT → 中间 JSON。
4. 删除 job 目录与中间 SRT。

可配置项：模型、aligner、backend、源语言（默认 `ja`）。

长音频切段（vt 的 `_split_audio`）放到后续版本；v1 先整文件听写。

### 4.4 小参数模型矫正（可选，新建）

vt 没有这一阶段。ASR 之后、gt 翻译之前，用小模型只修听写错误。

- 输入 / 输出都是中间 JSON。
- 约束：不翻译、不解释、不改时间戳、不增删句（允许合并明显碎句时需另开开关，v1 默认不合并）。
- 接口：OpenAI 兼容；可与翻译共用端点但使用不同模型，或走本地 llama.cpp。
- **不**复用 gt 的 ForGal 翻译模板，避免模型把「矫正」做成「翻译」。

### 4.5 大参数模型翻译（可选，直接调 gt）

每文件一个隔离的 gt 工程：

```text
workspace/
  config.yaml
  gt_input/
  gt_output/
  transl_cache/
```

调用方式：

```python
from GalTransl.Service import JobSpec, run_job_async

spec = JobSpec(
    project_dir=workspace,
    translator="ForGal-json",          # 或 sakura-v1.0 / galtransl-v3
    config_file_name="config.yaml",
)
state = await run_job_async(spec, stop_event=stop_event)
```

默认组合：

- 听写 JSON → 插件 `file_galtransl_json` + 引擎 `ForGal-json`。
- 纯字幕输入也可改用 `file_subtitle_srt_lrc_vtt`，v1 仍建议先转中间 JSON，路径统一。
- 在线后端走 gt 的 `OpenAI-Compatible`。
- 本地 Sakura / GalTransl 模型走 gt 的 `SakuraLLM`；llama-server 由 kt 启动，多文件共享一份进程。
- 字典、目标语言、prompt、并发、问题分析全部写进该 workspace 的 `config.yaml`，由 gt 自己执行。

进度：订阅 gt 日志中的关键状态（开始翻译、结果保存、总耗时），转发给 UI。支持取消（`stop_event` → `JobCancelledError`）。

### 4.6 导出

kikoeta 歌词库支持 `.lrc` / `.txt` / `.srt` / `.vtt` / `.ass` / `.ssa`，匹配分 `.lrc` 最高。解析时 `LyricLine.jp` 与 `LyricLine.zh` 目前填同一文本，文件名中的 `zh` 等标记会提高命中。

输出格式为四选一：

- 目标 LRC / 目标 SRT：只写译后文本（关闭翻译则为原文）。
- 双语 LRC / 双语 SRT：同一文件内译文 + 原文。

默认 **目标 LRC**。不再并列导出 VTT，也不再额外写 `.jp` / `.zh` / `.combine` 文件。

输出目录留空时，写到每个源文件所在目录；填写后所有任务产物都进该目录。

进阶：按作品号写入 kikoeta 便携目录：

```text
<kikoeta.exe 同级>/lyrics/RJ######/{stem}.lrc
```

kikoeta 歌词库作品号只接受 `RJ|VJ|BJ` + 数字。kt 从路径或文件名提取作品号；提取失败则写到用户指定输出目录，不强行进歌词库。

## 5. 与现有项目的关系

### 5.1 相对 kikoeta

| 能力 | kikoeta | kt |
| --- | --- | --- |
| 标题 / 文件名翻译 | 已有（Google / Edge / DeepL / OpenAI） | 不做 |
| 媒体听写 | 无 | 做 |
| 字幕 / 歌词翻译 | 无 | 做 |
| 播放与歌词显示 | 做 | 不做 |
| 平台 | Win + Android | 仅 Win（Mac / Linux 计划中） |

后期可选：kikoeta「发送到 kt」或直接打开 kt 输出目录。v1 只保证文件格式兼容。

### 5.2 相对 vt

复用思路，不复用 UI 与翻译调用方式：

- 复用：ffmpeg 参数、UVR ONNX、CrispASR 命令组装、SRT ↔ JSON、可选切段。
- 不复用：PyQt 界面、YouTube/Bilibili 下载、视频压字幕、总结、用子进程跑 gt。

### 5.3 相对 gt

- 仓库内包含完整 gt 源码与插件、字典、translation_guidelines。
- 只把 gt 当库：`Runner.run_galtransl` / `Service.run_job_async`。
- 不启动 gt 桌面端（Tauri）或公开端口的 gt server。
- 配置从 kt UI 生成 `config.yaml`，映射 gt 的 `backendSpecific` / `plugin` / `common` / `dictionary` / `proxy`。

## 6. UI

只做桌面。宽屏用 `NavigationRail`，视觉对齐 kikoeta：

- 配色：`AppColors` 蓝系深色 / 浅色（`bg #0B0E15`，`accent #4F8EF7`）
- 字体：SarasaUI
- 卡片：16 圆角、`surface` 底、细描边
- 控件：开关行、分组标题、测试连接按钮，对齐 kikoeta 设置页的 `_group` / `_row` / `_switchRow`

页面：

1. **任务**：拖放文件 / 文件夹、队列、阶段开关（UVR / 矫正 / 翻译）、开始 / 停止、实时日志与当前阶段。ASR 不作为开关：媒体任务固定开启，字幕任务固定跳过。
2. **模型**：ASR 模型 / aligner / backend / 源语言，矫正模型，gt 翻译器 / 目标语言。可输入下拉；ASR 扫描本地 gguf，矫正与翻译可查询 OpenAI 兼容 `/v1/models`。
3. **听写参数**：CrispASR 听写参数（高级模板置顶、基础分段、VAD/标点、解码、设备）。高级模板会随结构化参数实时生成，也可手动编辑；保存时会将模板中的可编辑参数反向同步到控件。默认使用 `firered` VAD、阈值 `0.5`、最大语音时长 `6s`、最小静音 `300ms`、`224` 个新 token、频率惩罚 `0.0`、温度 `0.0` 并按标点切分；VAD 模型支持 `auto`、`silero`、`firered`、`marblenet`、`webrtc`、`whisper-vad`，也可手动输入路径。字幕输入不会走到 ASR。
4. **模型参数**：分别配置矫正模型与 gt 翻译模型的 Prompt、采样和请求参数。翻译 Prompt 支持衔接到 gt 默认提示词尾部，或直接覆盖 gt 默认提示词。
5. **字典**：展示 `engine/GalTransl/Dict` 内置译前 / GPT / 译后字典，点击在 kt 内置编辑器中打开。翻译时由 gt 直接加载，不覆盖这些文件。
6. **输出**：四选一格式（目标 LRC / 目标 SRT / 双语 LRC / 双语 SRT）、输出目录（留空则写到源文件目录）、是否写入 kikoeta 歌词库。
7. **设置**：ffmpeg / CrispASR 路径可刷新检测，以及代理、UVR 模型等。默认 HTTP 代理为 `http://127.0.0.1:7890`。

阶段开关放在任务页顶部，关闭的阶段在进度条中直接跳过，不要藏进深层设置。转码与媒体 ASR 不是开关，进度条中始终显示。

## 8. 任务生命周期

1. UI 提交任务：文件列表 + 阶段开关 + 模型配置。
2. engine 为本次运行创建 `work/{job_id}/`。
3. 逐文件进入 pipeline；每阶段写状态事件。
4. 最终产物复制到用户输出目录（或 kikoeta 歌词库）。
5. `finally` 删除 wav、UVR 中间件、ASR job 目录；gt `transl_cache` 默认保留以便断点续翻，设置中可改为随任务清理。

状态机（单文件）：`queued → transcoding → separating → asr → correcting → translating → exporting → done / failed / cancelled`。关闭的可选阶段从状态机中省略；媒体文件的 `transcoding` 与 `asr` 不可省略，字幕文件从矫正或导出进入。

## 9. 范围

v1 做：

- 本地文件输入（媒体 + 字幕 / 歌词）
- 转码 / UVR / ASR / 矫正 / gt 翻译
- LRC / SRT / VTT 导出
- Flutter 桌面 UI
- 可选写入 kikoeta 歌词库

v1 不做：

- vt 的链接下载、音频切段合并、视频合成、字幕总结
- 嵌进 kikoeta 播放器
- 移动端
- 标题 / 文件名翻译（仍由 kikoeta 负责）

## 10. 落地顺序

1. engine 骨架 + 转码 + 字幕解析 + 导出 LRC / SRT
2. 进程内接入 gt 翻译（先跑通字幕输入）
3. CrispASR 听写
4. UVR 人声分离
5. 小参数模型矫正
6. Flutter UI 与进度对接
7. 写出到 kikoeta 歌词库；可选从 kikoeta 唤起

## 11. 默认决策

以下作为实现默认值，若需更改再改方案：

- 独立伴侣，不嵌入 kikoeta。
- Flutter UI + Python engine，不复刻 PyQt。
- 音频 / 视频必须 ASR；只有直接输入字幕 / 歌词才跳过听写。
- ASR 使用 CrispASR，不先上 Faster-Whisper。
- 矫正为独立模块，不走 ForGal 翻译模板。
- 翻译默认 `ForGal-json` + `file_galtransl_json`。
- 默认输出译后 `.lrc`。
- 长音频切段、kikoeta 内唤起放到 v1 之后。
