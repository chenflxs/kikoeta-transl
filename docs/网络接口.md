# 网络接口文档

本文件说明当前 engine 提供的 HTTP 接口。第三方集成应使用受版本管理的 `/api/v1` 接口；`/api` 仅供本项目 Flutter 桌面端使用，字段可能随界面调整。

本地桌面端新增 `GET /api/recent` 列出最近翻译结果和工作缓存，`DELETE /api/recent/{job_id}/cache` 仅删除指定任务的 GalTransl 工作缓存，不删除导出文件或 `/api/v1/cache` 的 Kikoeta 同步缓存。这两个接口不会暴露在远程 API 服务端口。

## 服务地址与安全

engine 启动后会创建两个 HTTP 服务：

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| 本地 engine | `http://127.0.0.1:18765` | 桌面端控制与本地调试。启动参数可修改 host 和 port。 |
| 远程 API | `http://127.0.0.1:2370` | kikoeta / 局域网客户端使用的 `/api/v1` 接口。启用“远程访问”后绑定 `0.0.0.0:2370`。 |

`/api/v1/*` 的每个请求都必须使用 HTTP Basic Authentication。用户名和密码在应用“设置”页配置；请在启用远程访问前修改默认凭据。服务使用明文 HTTP 且响应带有宽松的 CORS 头，不应直接暴露在互联网或不可信网络中。建议仅在可信局域网中使用，并通过防火墙限制来源。

下文以环境变量为例：

```powershell
$baseUrl = 'http://127.0.0.1:2370'
$user = '你的用户名'
$password = '你的密码'
```

PowerShell 调用时可构造 Basic Auth 请求头：

```powershell
$token = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("${user}:${password}"))
$headers = @{ Authorization = "Basic $token" }
```

下面的 curl 示例可直接用 `-u "用户名:密码"` 代替该请求头。

## `/api/v1` 远程接口

### 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/health` | 服务健康检查。 |
| `POST` | `/api/v1/jobs` | 创建远程翻译任务。 |
| `GET` | `/api/v1/jobs/{job_id}` | 查询任务状态和结果。 |
| `POST` | `/api/v1/jobs/{job_id}/cancel` | 请求停止任务。 |
| `POST` | `/api/v1/jobs/{job_id}/preempt` | 立即请求中断当前阶段并暂存任务。 |
| `GET` | `/api/v1/jobs/{job_id}/events?after={cursor}` | 获取任务事件（最长等待 20 秒）。 |
| `GET` | `/api/v1/jobs/{job_id}/outputs` | 列出当前任务的输出文件路径。 |
| `GET` | `/api/v1/jobs/{job_id}/files/{index}` | 下载某个任务输出文件。 |
| `GET` | `/api/v1/cache` | 列出 kikoeta 歌词缓存。 |
| `GET` | `/api/v1/cache/{job_id}/files/{index}` | 下载缓存的歌词文件。 |

除文件下载外，响应均为 `application/json; charset=utf-8`。发生错误时响应结构为：

```json
{"error": "错误说明"}
```

常见状态码：`400` 请求格式或下载失败、`401` 缺少或错误的认证信息、`404` 资源不存在、`409` 任务状态不允许该操作、`500` 服务内部错误。

### 健康检查

```bash
curl -u "用户名:密码" http://127.0.0.1:2370/api/v1/health
```

示例响应：

```json
{
  "ok": true,
  "name": "kikoeta-transl",
  "revision": 7,
  "service": "remote"
}
```

### 创建任务

`POST /api/v1/jobs` 在输入下载或上传完成后返回任务 ID，并开始一个工作流。Transl 同时只处理一个工作流，不维护等待队列；增删和顺序由 Kikoeta 管理。当前工作流尚未结束或暂存完成时，新提交返回 `409`。`files` 必须是非空数组；远程客户端应为每个输入文件提供 `url` 或 `content_base64`，二者必须且只能出现一个。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `files` | array | 是 | 输入文件列表。 |
| `files[].url` | string | 二选一 | 可下载的绝对 HTTP/HTTPS 地址。支持重定向；单个文件上限 2 GiB。 |
| `files[].content_base64` | string | 二选一 | 文件的 Base64 内容。 |
| `files[].name` | string | 否 | 下载或上传后使用的文件名；省略时从 URL 推导。 |
| `files[].headers` | object | 否 | 下载 URL 的附加请求头；仅允许 `Authorization` 和 `Cookie`。 |
| `flags.enable_correct` | boolean | 否 | Kikoeta 请求始终启用听写矫正；该字段为兼容保留，传 `false` 也不会关闭。 |
| `flags.enable_translate` | boolean | 否 | 是否启用翻译，默认 `true`。 |
| `settings` | object | 否 | 本次任务的设置覆盖项，按嵌套字段合并，不会写回本机设置。 |
| `cache.work_id` | string | 否 | kikoeta 工作标识；与 `track_paths` 同时提供时启用 LRC 缓存。 |
| `cache.track_paths` | string array | 否 | 与输入文件顺序对应的 kikoeta 曲目路径。 |

下载源示例：

```json
{
  "files": [
    {
      "url": "https://media.example.com/episode-01.mkv",
      "name": "episode-01.mkv",
      "headers": {"Authorization": "Bearer download-token"}
    }
  ],
  "flags": {
    "enable_correct": true,
    "enable_translate": true
  },
  "settings": {
    "source_lang": "ja",
    "target_lang": "zh-cn",
    "output": {"preset": "bilingual_lrc"}
  },
  "cache": {
    "work_id": "EXAMPLE-ALBUM",
    "track_paths": ["01 - Example Song.mp3"]
  }
}
```

```bash
curl -u "用户名:密码" \
  -H "Content-Type: application/json" \
  -X POST http://127.0.0.1:2370/api/v1/jobs \
  --data @request.json
```

Base64 上传的最小示例：

```json
{
  "files": [
    {
      "name": "song.srt",
      "content_base64": "MTowMDowMCwwMDAgLS0+IDA6MDA6MDEsMDAwCuOBk+OCk+OBq+OBoeOBrw=="
    }
  ]
}
```

成功时返回 `201 Created`。`results` 按输入顺序保留占位项；尚未处理的项状态为 `queued`，没有输出：

```json
{
  "job_id": "a1b2c3d4e5f6",
  "status": "running",
  "source": "kikoeta",
  "created_at": "2026-09-13T00:00:00+00:00",
  "flags": {"enable_correct": true, "enable_translate": true},
  "work_id": "EXAMPLE-ALBUM",
  "total_files": 1,
  "completed_files": 0,
  "event_cursor": 0,
  "files": ["服务端输入文件路径"],
  "results": [{"path": "服务端输入文件路径", "kind": "media", "status": "queued", "stage": "queued", "outputs": [], "download_urls": [], "message": "", "error": ""}],
  "error": ""
}
```

远程下载或 Base64 上传的原始输入在完成、失败或取消后清理，暂存期间保留。直接传入字符串形式的 `files` 仅适合与 engine 位于同一台机器的本地调试；不要把它作为跨主机的文件传输方式。

### 插队与暂存恢复

Kikoeta 需要插队时，先调用下列接口中断并暂存当前工作流；确认其状态为 `paused` 或已经结束后，再用原有创建接口提交目标作品。

```bash
curl -u "用户名:密码" -X POST \
  http://127.0.0.1:2370/api/v1/jobs/a1b2c3d4e5f6/preempt
```

运行中的任务先进入 `pausing`，停止当前阶段后进入 `paused`。响应表示已接受停止请求，客户端应继续轮询至 `paused`，或任务恰好已经结束。停止通过现有协作式取消检查执行，ffmpeg/ASR 子进程会被终止；已经发给外部服务的请求可能仍由外部服务执行，其迟到响应不会用于本次任务。

例如 5 个文件已完成前 2 个、第 3 个正在处理，插队后前 2 个的导出结果和输入保留，第 3 个中断。原任务不会自行恢复。Kikoeta 再次以相同 `cache.work_id`、相同顺序的 `cache.track_paths`、相同阶段开关和生效设置提交该作品时，会复用原任务 ID，跳过已完成且输出仍存在的文件，从第 3 个重新处理。文件内部不保证从中断句继续。更换轨道、顺序或配置会创建新任务；旧暂存任务仍保留。

每个文件完成及任务状态变更时，检查点保存在 `engine/work/{job_id}/`，不会进入导出或下载列表。引擎重启后未完成任务恢复为暂存状态，等待 Kikoeta 再次请求该作品；不会自动启动模型。暂存任务需先取消，才可删除最近记录或工作缓存。

`completed_files` 是已完成文件数，`total_files` 是输入总数。恢复请求响应中的 `event_cursor` 用于从本轮事件起点继续长轮询，避免重复消费上一轮的完成/暂存事件。轨道应通过完整 `files` 列表和结果 `path` 对应，不要按已完成文件数压缩下标。

### 查询、取消与事件

`GET /api/v1/jobs/{job_id}` 返回任务状态。任务状态包括 `queued`、`running`、`pausing`、`paused`、`completed`、`failed`、`cancelled`。`paused` 表示本轮处理结束并保留结果；客户端应停止本轮等待，等下次恢复请求。每个 `results` 项包含 `path`、`kind`、`status`、`stage`、`message`、`outputs`、`error` 和 `download_urls`；仅下载 `status: "done"` 的结果，并使用 `download_urls`，不要依赖服务端本机的 `outputs` 路径。

```bash
curl -u "用户名:密码" http://127.0.0.1:2370/api/v1/jobs/a1b2c3d4e5f6
curl -u "用户名:密码" -X POST http://127.0.0.1:2370/api/v1/jobs/a1b2c3d4e5f6/cancel
```

`GET /api/v1/jobs/{job_id}/events?after={cursor}` 是 JSON **长轮询**，不是 Server-Sent Events。没有新事件时服务最多等待 20 秒；收到响应后，使用返回的 `cursor` 立即发起下一次请求即可。

```json
{
  "events": [
    {"type": "status", "stage": "asr", "file": "episode-01.mkv", "message": "ASR 听写"},
    {"type": "log", "message": "…"}
  ],
  "cursor": 2,
  "closed": false
}
```

事件类型包括 `status`、`log`、`file_done`、`file_error` 和 `job_done`。收到 `job_done` 或 `closed: true` 时，应查询任务详情，以最新状态判断本轮结束。恢复会沿用任务 ID；旧事件中的 `job_done` 不代表恢复后的任务已结束。

### 下载任务输出

任务完成后可先读取输出列表：

```bash
curl -u "用户名:密码" http://127.0.0.1:2370/api/v1/jobs/a1b2c3d4e5f6/outputs
```

再使用任务详情中 `download_urls` 的相对路径下载。例如：

```bash
curl -u "用户名:密码" -o output.lrc \
  http://127.0.0.1:2370/api/v1/jobs/a1b2c3d4e5f6/files/0
```

### kikoeta 歌词缓存

当创建任务时同时传入有效的 `cache.work_id` 和 `cache.track_paths`，并且任务成功生成 LRC 文件后，服务会保留最近最多 5 条缓存记录。缓存列表的每个文件会携带相对 `download_url`：

```json
{
  "entries": [
    {
      "job_id": "a1b2c3d4e5f6",
      "work_id": "EXAMPLE-ALBUM",
      "completed_at": "2026-09-13T00:05:00+00:00",
      "files": [
        {
          "track_path": "01 - Example Song.mp3",
          "name": "episode-01.zh.lrc",
          "download_url": "/api/v1/cache/a1b2c3d4e5f6/files/0"
        }
      ]
    }
  ]
}
```

## 本地桌面端接口

默认本地 engine 的 `http://127.0.0.1:18765` 还提供以下未版本化接口。它们不接受远程 API 的文件上传格式，主要供 `app/` 调用；在远程服务端口 `2370` 上访问这些路径会得到 `404`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/health` | 本地服务健康检查。 |
| `GET` / `PUT` | `/api/settings` | 读取或完整保存应用设置。 |
| `GET` | `/api/tools` | 工具、ASR 模型、字典和语言目录。 |
| `GET` / `POST` | `/api/jobs` | 本地文件路径任务列表与创建。 |
| `GET` | `/api/jobs/{job_id}` | 获取本地任务详情。 |
| `GET` | `/api/jobs/{job_id}/events?after={cursor}` | 本地任务长轮询事件。 |
| `POST` | `/api/jobs/{job_id}/cancel` | 请求取消本地任务。 |
| `POST` | `/api/jobs/{job_id}/preempt` | 中断并暂存当前工作流，与远程接口语义相同。 |
| `POST` | `/api/models/openai` | 查询 OpenAI 兼容服务的模型列表。 |
| `POST` | `/api/test/correct` | 测试已保存的矫正模型配置。 |
| `POST` | `/api/test/translate` | 检查翻译后端是否已配置。 |
| `POST` | `/api/client-heartbeat` | 桌面端保活信号，仅允许本机调用。 |
| `POST` | `/api/shutdown` | 停止 engine，仅允许本机调用。 |

本地任务接口的 `files` 是 engine 所在机器可访问的文件路径。不要在生产集成中把 `/api/settings`、`/api/shutdown` 或本地端口暴露到网络。

## 向 Kikoeta-LLS 同步产物

“输出”页的 `output.lls_sync` 仅对来自 Kikoeta、成功完成并带有有效 RJ/VJ/BJ 作品号与曲目路径的任务生效。创建任务时会读取本机保存的同步配置，远程任务的 `settings` 覆盖项不能替换 LLS 的上传地址或凭据。上传失败会记录在任务事件日志中，不会删除本地输出或 Kikoeta 缓存。

`output.lls_url` 留空时使用 `http://127.0.0.1:2378`。`output.lls_auth_mode` 可选 `key` 或 `basic`，分别使用 `output.lls_key`，或独立的 `output.lls_username`、`output.lls_password`。这些值保存在本机 `engine/data/settings.json`，不要将该文件提交到仓库。LLS 写入接口与本服务的 2370 远程 API 凭据相互独立。
